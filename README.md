# ANVIL

**ANVIL** — ультралёгкий терминал для тех, кто работает в CLI: Claude Code,
OpenCode, OMP и другие агентные оболочки. Вертикальные вкладки, сплиты, панель
git прямо в пейне и статус Claude Code — без Electron, Node и интерпретатора
в поставке: один exe и две dll. Написан на Rust, рисуется через egui/OpenGL,
запускает оболочку на встроенном ConPTY. Автор — rercon prod.

## Возможности

**Вкладки и пейны**
- Вертикальный список вкладок: номера, заголовок, точка активности, бейдж Claude;
  перетаскивание для смены порядка, переименование по правому клику.
- Сплиты вправо и вниз, навигация между пейнами, максимизация пейна,
  сворачивание в чип в полосе над терминалом.
- Неактивные пейны притемняются, чтобы взгляд держался на том, куда печатаешь.
- Сессия восстанавливается при запуске: вкладки, сплиты, рабочие каталоги,
  открытая панель и её вкладка.

**Терминал**
- Полноценный VTE-разбор (`alacritty_terminal`): 256/truecolor, курсор, режимы
  мыши, bracketed paste, OSC 8-ссылки, OSC 7/1337 — панель следует за `cd`.
- Поиск по буферу (Ctrl+Shift+F), скроллбек, выделение мышью и вставка средней
  кнопкой. Копирование при выделении включено по умолчанию: отпускание кнопки
  копирует текст без тоста и не снимает подсветку. Отключается в «Настройки →
  Терминал → Копировать при выделении» (`terminal.copyOnSelect=false`).
  В приложениях с захватом мыши выделение доступно с зажатым Shift.
- Вставка безопасна по умолчанию: управляющие символы (включая ESC и закрывающий
  bracket `ESC[201~`) вырезаются в обоих режимах, вложения bracketed paste
  формирует только сам ANVIL. Многострочный текст при выключенном bracketed
  paste не отправляется молча: показывается неизменяемый предпросмотр точных
  байтов, Enter по умолчанию отменяет, вставка требует явной кнопки.
- Вывод приложения в терминал не может незаметно подменить буфер обмена: OSC 52
  выключен по умолчанию, включается переключателем в «Настройки → Терминал».
- Блочные элементы (`█ ▀ ▐ ▛ ▝ …`) рисуются ровно в клетку, поэтому ASCII-арт
  вроде маскота Claude Code собирается в картинку, а не рассыпается.
- Braille-глифы (`U+2800…U+28FF`), включая спиннер OMP, рисуются фиксированной
  сеткой 2×4 точки внутри клетки: масштаб и положение точек не меняются между
  кадрами. Braille и блочная графика не требуют системных fallback-шрифтов.
- Масштаб текста: Ctrl+= / Ctrl+- / Ctrl+0, размер показывается тостом.
- Шрифт интерфейса — Cascadia Mono (вшита), терминал берёт системное семейство
  из настроек; недостающие глифы подтягиваются из системных шрифтов.
- Символы fallback-шрифтов вписываются в клетку и выравниваются по основному
  тексту: стрелки режима разрешений Claude Code не опускаются ниже строки.
- Сплошной и контурный курсор выравниваются по центру видимого текста, а не
  полной высоты строки с запасом под выносные элементы: в поле Claude Code
  квадратный курсор не опускается ниже середины. Терминальная сетка и базовая
  линия символа под курсором при этом не меняются.

**Панель git** (у каждого пейна своя, Ctrl+Shift+G)
- Статус, стейджинг по файлам и **по отдельным ханкам**, дифф с номерами строк
  и полосами изменений, как в привычных difftool.
- Коммит: сообщение вручную или ИИ-командой (`claude`, `opencode`, `codex`…).
  ИИ получает только изменения из индекса, поэтому сообщение описывает ровно
  то, что уйдёт в коммит. ИИ пишет подробное многострочное описание без лимита
  в 72 символа и без обрезания тела; во время генерации видны анимированный
  индикатор и статус. Поле сообщения имеет ограниченную высоту и внутреннюю
  прокрутку, поэтому длинный коммит не растягивает окно и не скрывает кнопки;
  рамка поля остаётся неподвижной при прокрутке текста.
- В просмотре созданного коммита полное сообщение и список файлов прокручиваются
  вместе, без обрезания сообщения; кнопки навигации остаются сверху. Нажатие на
  файл открывает только его diff, «назад» возвращает к прежнему месту в списке,
  а «Копировать патч» копирует только выбранный файл.
- В **Настройках → Панель git** можно выбрать модель OpenCode из списка
  подключённых провайдеров и отфильтровать его, например по `DeepSeek`.
  Выбор сохраняется в `workspace.aiCommitModel` (`provider/model`); вариант
  «По умолчанию в OpenCode» оставляет выбор самому CLI. Ключи провайдеров
  подключаются через `opencode auth login`, а не хранятся в ANVIL.
- OpenCode в Windows запускается непосредственно как `.exe`, в том числе при
  установке через npm; устаревший PATH окна не мешает найти стандартную
  установку. Коммит пишет отдельный агент без инструментов и внешних плагинов:
  он получает готовый diff, не запускает git/bash и не ищет репозиторий.
  Остальные npm-CLI (`codex`, `gemini`, `claude`) стоят за `.cmd`-шимами; панель
  разворачивает такой шим в `node` со скриптом, потому что `cmd.exe` не
  принимает многострочные аргументы, — промпт с diff доходит целиком.
- ИИ-генерация не выполняет код по инструкции из диффа ни для одного из
  поддерживаемых CLI. Claude идёт в режиме `--bare` (API-ключ) или
  `--safe-mode --restricted` с закрытыми инструментами, MCP, slash-командами и
  хуками; при корпоративной managed-политике с исполняемыми хуками генерация
  отказывает до запуска — административные хуки отключить нельзя, а обойти их
  ANVIL не пытается. Gemini запускается с `tools.core=[]`, отключёнными хуками,
  расширениями и MCP. OpenCode получает изолированный профиль (свой XDG-каталог,
  `--pure`, агент с закрытыми правами), aider — нативный inference-вызов через
  свой venv-Python без `main()` и без чтения `.aider.conf.yml`. Codex работает
  напрямую по официальному Responses-протоколу (`tools` не передаются,
  `tool_choice=none`, события инструментов не исполняются) — он входит в сборку
  только с `--features codex` (см. «Сборка»), потому что тянет HTTP-клиент с TLS
  и заметно увеличивает exe; без этой сборки бэкенд отвечает, как его включить.
  Учётные данные не попадают в командную строку: `--settings` у Claude содержит
  только инертные настройки модели, а ключи и токены передаются окружением.
  ANVIL не обновляет OAuth-токены Codex — при истёкшем входе он просит выполнить
  `codex login`, чтобы ротация токена не сломала вход самого Codex CLI. Каждый
  вызов идёт в
  приватном временном каталоге, который удаляется после ответа; брошенные
  каталоги старше часа подчищаются при старте ANVIL и перед следующей
  генерацией — копии учётных данных не переживают падение процесса. Незнакомые
  флаги, обёртки и нечитаемые политики — явная ошибка, а не тихий откат в
  небезопасный режим.
- Push и fetch, граф коммитов с цветами по секциям (синие — не отправленные,
  бледно-розовые — в истории, сиреневые — входящие).
  После успешного push/fetch история обновляется автоматически, а изменения
  HEAD и upstream, сделанные вне панели (в терминале рядом или другим клиентом),
  подхватываются опросом: отправленные коммиты переходят в историю, входящие
  появляются отдельной секцией, цвета секций и метки веток обновляются по новым refs.
- Подтверждение доверия панель спрашивает только тогда, когда конфигурация
  репозитория действительно может запускать программы: фильтры, `core.fsmonitor`,
  внешние diff-драйверы, программы подписи, credential/ssh-хелперы,
  `core.hooksPath`, include-файлы, транспорт `protocol.*` и подмены
  `url.*.insteadOf/pushInsteadOf`, `remote.*.vcs`, `submodule.<имя>.update = !…`.
  Обычные ключи (ветки, remote, редактор, формат лога, `submodule.<имя>.url` и
  `.active`) доверия не требуют: репозиторий без таких настроек открывается
  сразу, а `push --set-upstream`, `checkout -b` и `submodule init/sync`
  разрешение не сбрасывают. В запросе перечислены сами ключи — видно, что именно
  может запуститься.
- До первого вызова git ANVIL сам, без запуска git, читает `.git`-файл
  git-репозитория, локальный и включаемые конфиги: пути, ведущие на сетевые и
  device-директории (`\\…`, `\\?\UNC`, `\\.\`, URL-формы), junction/symlink-цели
  и UNC в `core.attributesFile` отклоняются до любого касания метаданных, чтобы
  репозиторий не мог вызвать NTLM-аутентификацию или обратиться к чужому диску
  ещё до вопроса о доверии. Отказ — явное сообщение, а не тихое продолжение.
- Разрешение действует в этой сессии для репозитория целиком: его видят все
  пейны и вкладки процесса, повторный запрос не появляется. Окно, открытое
  `Ctrl+Shift+N`, — отдельный процесс и спросит один раз заново (разрешение
  живёт только в памяти и на диск не пишется). Изменение
  опасного ключа сбрасывает разрешение, но черновик сообщения коммита
  сохраняется. До подтверждения ANVIL не читает статус, diff и историю и не
  выполняет Git-действия; файлы хуков в отпечаток не входят — они запускаются
  только действиями, которые вы сами инициируете, как в обычном CLI. Подписи
  коммитов и внешние diff/textconv-драйверы при автоматической работе панели не
  проверяются и не запускаются.
- Дерево файлов (свёрнуто по умолчанию, поиск — как раньше, по нечёткому
  совпадению), превью файла с нумерацией строк и **рендером Markdown**
  (заголовки, списки, цитаты, код, таблицы, инлайн-разметка), кнопка подсчёта
  строк проекта. Дифф, превью и дерево рисуются по видимой области: строки
  раскладываются не целиком в каждом кадре, а по мере прокрутки, и кэш
  сбрасывается только при реальном изменении содержимого, ширины, DPI или
  шрифта. Открытый дифф не перезапрашивается на каждом опросе, а превью читает
  файл до 8 МиБ (дальше — заметная пометка об усечении). Удаление из дерева
  после подтверждения переносит папку целиком
  — вместе со скрытыми и игнорируемыми файлами — в корзину Windows; отмена или
  ошибка оставляют её на месте, без безвозвратного удаления.
- «Открыть в системе» использует белый список форматов, которые показываются, а
  не исполняются (текст, изображения с проверенной сигнатурой, PDF): программы,
  скрипты, ярлыки и неизвестные типы — включая `.sh`, `.pyz`, `.msix`,
  `.appinstaller`, `.rdp`, `.website` — не запускаются, а подсвечиваются в
  проводнике. Перед открытием путь проходит через `resolve_path`, поэтому
  выход за корень репозитория, ADS и reparse-перенаправления отклоняются.

**Claude Code**
- Строка состояния в панели вкладки: модель, заполнение контекста, лимиты 5ч/7д.
  Интеграция выключена по умолчанию и никогда не пишет глобальный
  `~/.claude/settings.json` сама: установка и обновление пути — отдельный диалог,
  который показывает файл, текущую и новую команду; отключение возвращает
  прежнюю строку, если её не изменили.
- Долгие проверки не блокируют интерфейс: список дистрибутивов WSL ищется в фоне
  с дедлайном (сохранённый профиль WSL работает сразу, до ответа `wsl.exe`),
  список системных шрифтов кэшируется и обновляется кнопкой, а реестр не
  читается в каждом кадре.

## Долгие CLI-сессии

- История ограничена `terminal.scrollback`: по умолчанию 25 000 строк на пейн.
  Настройка применяется к уже открытым пейнам; история не урезается отдельным
  скрытым лимитом. Больше строк и шире сетка — больше памяти под ячейки.
- События пейна не накапливаются за скрытым или заблокированным интерфейсом:
  между кадрами хранятся только последние заголовок, запрос копирования,
  состояние мигания, сигнал звонка и завершение процесса. Повторные запросы
  перерисовки объединяются до следующей обработки пейна.
- Кэш покрытия шрифта ограничен 4096 символами на пейн, общий DirectWrite-кэш —
  16 384 записями. Буферы текста видимых строк переиспользуются между кадрами.
- OSC ограничен 1 МиБ до передачи VTE-парсеру. Слишком длинная последовательность
  отбрасывается целиком, без применения усечённого заголовка, ссылки или OSC 52.
  Обычный вывод и CSI-перерисовки не копируются через этот защитный буфер.
- Эти ограничения не являются общим потолком памяти: у Alacritty остаются
  неограниченный список combining-символов в одной ячейке и очередь ввода, если
  дочерняя программа перестала читать stdin. Для них требуется отдельный контракт
  ограничения хранения и обратного давления, без потери пользовательского текста.
  Память контекста OpenCode, OMP, Claude Code и Codex принадлежит самим CLI,
  а не терминалу; ANVIL не обрезает их контекст и не завершает живые сессии.


## Требования

- Windows 10/11 **x64** (в поставке вендоренный ConPTY; другие архитектуры не
  поддерживаются осознанно — см. `build.rs`). При старте ANVIL запрещает
  загрузчику Windows искать DLL в рабочем каталоге и `PATH`
  (`SetDefaultDllDirectories`): неявно загружаемые библиотеки берутся только из
  папки рядом с `anvil.exe` и из `System32`, поэтому распакованный чужой
  репозиторий не может подсунуть свой `conpty.dll` или другую библиотеку.
- Rust 1.88+ с MSVC-тулчейном (для сборки из исходников).

## Сборка

```powershell
cargo build --release          # target\release\anvil.exe, без бэкенда Codex
cargo build --release --features codex   # + нативный Codex (HTTP-клиент с TLS)
cargo test                     # юнит-тесты, ConPTY и интеграционные git-тесты
cargo run --example gen_icons  # пересобрать иконки из icons/source/mark-chevron.png
```

По умолчанию Codex не входит в сборку: его HTTP-клиент (`reqwest`/`tokio`/
`hyper`/`rustls`) добавляет заметную часть размера release-exe, а остальные
AI-бэкенды обходятся штатными CLI. Ключ `--features codex` включает нативный
Responses-протокол; без него выбор Codex в настройках даёт понятную ошибку со
ссылкой на флаг.

Исходник логотипа — `icons/source/mark-chevron.png`: белый знак с тёмным
контуром без подложки. Генератор сохраняет прозрачность, обновляет иконку окна
и ICO с десятью размерами 16–256 пикселей. См. [описание иконки](icons/README.md).

Портативный архив с лицензиями и `SOURCE.txt`:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\package.ps1
# dist\anvil-<версия>-x64.zip
```

В архиве: `anvil.exe`, `anvil-claude-status.exe`, `conpty.dll`, `OpenConsole.exe`,
`LICENSE`, `LICENSES\**` (включая полный текст OFL для шрифтов) и `SOURCE.txt`.

## Горячие клавиши

Основные (полный список и переопределение — в настройках и `config.json`):

| Действие | Клавиши |
|---|---|
| Новая вкладка / окно | `Ctrl+Shift+T` / `Ctrl+Shift+N` |
| Закрыть / вернуть вкладку | `Ctrl+Shift+W` / `Ctrl+Shift+Z` |
| Следующая / предыдущая вкладка | `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| Вкладка по номеру | `Alt+1…9`, `Alt+0` |
| Сплит вправо / вниз | `Ctrl+Shift+S` / `Ctrl+Shift+D` |
| Перейти в пейн | `Ctrl+Alt+Стрелки` |
| Максимизировать пейн | `Ctrl+Alt+Enter` |
| Панель git | `Ctrl+Shift+G` |
| Поиск в терминале | `Ctrl+Shift+F` |
| Копировать / вставить | `Ctrl+Shift+C` / `Ctrl+Shift+V` |
| Масштаб текста | `Ctrl+=` / `Ctrl+-` / `Ctrl+0` |
| Выбор профиля | `Ctrl+Shift+E` |
| Настройки | `Ctrl+,` |
| Полный экран | `F11` |

## Настройки и файлы

- `%APPDATA%\anvil\config.json` — пишутся только значения, отличающиеся от
  умолчаний: шрифт, цветовая схема, профили, горячие клавиши, переключатель
  Claude Code, восстановление сессии, ИИ-команда и модель сообщения коммита.
  Файл можно править на ходу: приложение перечитывает его и не затирает
  частично записанный файл.
- `%APPDATA%\anvil\session.json` — окна, вкладки, сплиты и каталоги.
- `%APPDATA%\anvil\anvil.log` — журнал (с ротацией).
